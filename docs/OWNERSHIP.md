# APEX 소유권과 빌림 (M5)

**상태: 구현됨** (엘라보레이터의 변이 의미론 + `apex-borrowck`). 테스트는 `tests/run/{mutation,refmut,ownership}.apex`,
`tests/ui/check/{ok,err}/`, 그리고 `crates/apex-borrowck`의 단위 테스트 24개.

APEX는 순수 함수형 언어이고 커널은 증명을 검증한다. 그런데 Rust처럼 `&mut`와 소유권으로 쓰고 싶다.
이 문서는 둘을 어떻게 합치는지, 무엇을 검사하는지, 무엇을 아직 하지 않는지를 정한다.

## 1. 의미: 값 의미론의 참조

`&mut T`는 **포인터가 아니라 "T를 받아 T를 돌려주는" 관계**다 (copy-in / copy-out).

```apex
fn push_twice(v: &mut List<Nat>, x: Nat) {
    v = List.cons(x, v);       // v는 이 함수 안의 가변 지역 변수
    v = List.cons(x, v);
}

fn main() -> IO<Unit> {
    do {
        let mut xs := [1];
        push_twice(&mut xs, 7);   // xs := (push_twice의 결과로 갱신된 값)
        display(xs)               // [7, 7, 1]
    }
}
```

컴파일러는 이것을 순수 항으로 바꾼다. 커널은 변이를 모른다.

| 소스 | 커널 항 |
|---|---|
| `fn f(a: &mut A, n: Nat) -> R` | `f : Π (a : A) (n : Nat), Prod R A` (결과 쌍: 반환값과 갱신된 `a`) |
| `f(&mut x, 3)` | `let p := f x 3; let x' := p.snd; ..` 이후 `x`는 `x'`를 가리킨다. 값은 `p.fst` |
| `x = e;` | `let x' := e;` 이후 `x`는 `x'` (SSA 재바인딩) |
| `x.f = e;` | `let x' := S.mk(.., e, ..)` (구조체 갱신) |
| `x += e;` | `x = x + e;` |
| `if`/`match` 안의 변이 | 가변 변수들을 **쌍으로 묶어 분기 결과로 돌려주고**, 합류점에서 다시 바인딩 (phi) |
| `&e`, `*e` | 값 (`&T`는 `T`로 소거) |

`&mut` 인자가 여러 개면 갱신된 값들은 오른쪽으로 중첩된 쌍이다: `Prod R (Prod A1 A2)`.

그러므로 **증명과 커널은 그대로 유효하다.** 변이가 있는 함수에 대해서도 정리를 쓸 수 있다
(`push_twice` 의 타입은 평범한 순수 함수의 타입이다).

## 2. 왜 빌림 검사가 필요한가

copy-in / copy-out은 별칭이 없을 때만 포인터 의미와 같다. `f(&mut x, &mut x)`나 `&mut x`가 살아 있는 동안
`x`를 읽는 프로그램은 두 의미가 갈라진다. 그래서 빌림 검사기의 역할은 **별칭이 생기는 프로그램을 거부해서
값 의미론이 항상 참조 의미론과 같도록 보장하는 것**이다. 검사를 통과하면 "참조처럼" 읽어도 된다.

## 3. 검사하는 것 (`apex-borrowck`)

구조화된 코드(루프 없음, 재귀만)이므로 NLL은 단순한 활성(liveness) 분석이다:
빌림은 그 참조를 담은 변수가 **이후에 쓰이는 동안** 살아 있다.

| 오류 | Rust 코드 | 예 |
|---|---|---|
| 이동 후 사용 | E0382 | `own` 값을 넘긴 뒤 다시 씀 |
| 가변 빌림 둘 | E0499 | `f(&mut x, &mut x)` |
| 가변 + 공유 빌림 | E0502 | `f(&mut x, &x)`, `let r = &x; g(&mut x); use(r)` |
| 빌린 동안 대입 | E0506 | `let r = &x; x = 1; use(r)` |
| 빌린 동안 이동 | E0505 | `let r = &x; consume(x); use(r)` |
| 가변 빌림 중 읽기 | E0503 | `f(&mut x, x)` |
| 불변 변수에 대입 | E0384 | `let x := 1; x = 2;` (엘라보레이터) |
| 불변 변수를 가변 빌림 | E0596 | `let x := 1; f(&mut x)` (엘라보레이터) |
| 지역 변수 참조 반환 | E0515 | `fn f() -> &Nat { let x := 1; &x }` |
| 수명 지정 누락 | E0106 | 참조 반환인데 후보 인자가 없거나 둘 이상 |
| `own` 값을 비소유 매개변수로 이동 | (APEX) | 선형 값은 `own` 매개변수로만 넘길 수 있다 |

수명 생략 규칙은 Rust와 같다: 참조 반환에서 참조 매개변수가 정확히 하나이거나 `&self`가 있으면 그것에서 온다.
명시한 `'a`는 매개변수 어딘가에 나타나야 한다.

## 4. 이동과 복사

- 기본 값(ω)은 자유롭게 복사된다. 순수 데이터라 복사해도 의미가 같기 때문이다 (Rust의 `Copy`에 해당).
- `own x: T`는 선형(곱셈수 1): 정확히 한 번 쓰이고, 쓰면 **이동**한다. 커널의 곱셈수 검사가 한 번 더 보장한다.
- 이동은 값 자리에 변수를 그대로 쓰는 것 (`f(x)`, `let y := x`, 반환, 구조체 필드 값). `x.f`나 `&x`는 이동이 아니다.

## 5. 이번에 하지 않는 것 (솔직하게)

(아래는 모두 명확한 오류로 거부되며, `tests/ui/check/err/`에 테스트가 있다.)

- **지역 변수에 `&mut`를 저장** (`let r = &mut x;`). `&mut`는 호출 인자와 `&mut` 매개변수의 재빌림으로만 쓴다.
  (공유 참조 `let r = &x;`는 저장할 수 있다. 값 복사이므로.)
- **`&mut`를 반환**하는 함수.
- **`own` 값을 빌림**과 **`own` 구조체의 필드 읽기**. 선형 값을 소비 없이 읽으려면 커널에 "읽기 전용 사용"이 필요하고,
  필드 하나를 읽으면 나머지 필드가 버려지는 문제가 있다. 지금은 `own` 값을 그대로 다음 `own` 매개변수에 넘기는 용도.
- **`IO`를 돌려주는 함수의 `&mut` 매개변수**: 갱신된 값이 액션을 실행한 결과에 의존할 수 있다.
- **재귀 함수의 `&mut` 매개변수**와 `&mut` 부분 적용.
- **`for` 본문이나 클로저 안에서 바깥 가변 변수에 대입**. 본문은 함수이므로 상태를 돌려주는 형태로 바꿔야 한다. 오류로 거부한다.
- **재귀 함수 안의 변이**와 `match` 모티브 안의 `&mut` 상호작용.
- **Drop과 해제**. 순수 값에는 소멸자가 의미가 없다. 네이티브 백엔드(M7)에서 소유권 정보로 해제를 넣는다.
- 라이프타임 매개변수의 일반 추론, 구조체가 참조 필드를 가지는 경우, 라이프타임 경계 (`'a: 'b`).

## 6. 구현 메모

- **변이는 재바인딩이다.** 가변 변수는 스코프에서 이름 앞에 표식을 단 항목이고, 대입은 새 `let`을 효과 누산기(`lets`)에 쌓고
  그 이름이 새 변수를 가리키게 한다. 블록/클로저/분기/`match` 팔 같은 바인더가 자기 몫의 누산분을 감싼다.
- **분기**: `if`/`match`는 스코프의 가변 변수 전부를 `(값, 상태)` 쌍으로 돌려주고 합류점에서 다시 바인딩한다.
  `do` 안의 `if`/`match` 문장은 상태가 `IO` 액션의 결과(`bind` 뒤)에 의존할 수 있으므로, `let s <- if .. { ..; pure(상태) };
  w = s.fst; ..`로 AST 수준에서 바꾼다.
- **빌림 검사 위치**: 엘라보레이션이 끝난 뒤, 커널 검사 전. 엘라보레이터가 호출 지점(span)마다 호출 대상을 기록하고,
  검사기는 AST와 그 시그니처만 본다. 그래서 커널의 곱셈수 오류 대신 위치가 정확한 진단이 나온다.
- **NLL**: 2패스. 1패스는 변수의 마지막 사용 위치를 모으고, 2패스는 같은 순서로 걸으며 각 접근을 그 시점에 살아 있는 빌림과 비교한다.
  빌림은 그것을 담은 변수(클로저가 캡처했으면 클로저 변수도) 중 하나가 이후에 쓰이는 동안 산다.
- **두 단계 빌림**: `v.push(v.len())`처럼 `&mut self` 수신자의 빌림은 다른 인자를 읽은 뒤에 활성화된다.
- **분기의 이동**: `if`/`match`의 이동은 합집합이다 (한쪽에서 이동했으면 이후 사용은 오류).
- 시그니처 분석은 `callee_of` 하나가 맡고 (매개변수 종류, 수명 생략), 엘라보레이터의 `&mut` 변환과 검사기가 같이 쓴다.

## 7. 구성

- `crates/apex-borrowck`: AST와 호출 대상의 시그니처(`Callee`)만 입력으로 받는 분석. 커널/엘라보레이터에 의존하지 않는다.
- 엘라보레이터가 호출 지점의 대상을 기록해서 넘기고, 변이를 순수 항으로 바꾼다.
- 빌림 검사는 엘라보레이션이 끝난 뒤 커널 검사 전에 한다 (정확한 위치의 진단이 커널의 곱셈수 오류보다 먼저 나오도록).
